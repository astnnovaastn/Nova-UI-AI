# Supplied Memory Globe integration

## Engine and presentation
The production wrapper and adapter came from Downloads/files (2)/memory-globe-package/memory-globe. The later user-supplied Downloads/globeEngine.ts provides the current engine, with the integration patches below. It remains framework-free Canvas 2D with perspective 3D projection, spherical category patches, yaw/pitch rotation and inertia. Category groups exceeding 70 memories become dated patches. Fan, disc, rosette and spiral placements form the incomplete globe; entity relays occupy its inner volume. The globe and detail panel use --widget-surface. Settings → System Info → Memory remains the entry point, with the conversation rail and memory library.

The 27 authoritative category classes and their IDs remain intact. Up to 100 additional presentation topics form a maximum of 127 visible category/topic groups. These groups combine existing supported topics and deterministic matching of actual source text. They are content collections, not new user facts or invented causal relationships. Original record categories remain available even when records occupy more specific topic patches. Each category and entity has a stable palette color. Labels reveal important hubs progressively with overlap suppression.

## Shared data and privacy
The authoritative shared service supplies facts, events, historical context and effective attributed user/assistant transcript messages. IDs, revisions, original timestamps, session identities, provenance and evidence are retained. Private, expired, forgotten, inaccessible and incomplete conversation records are filtered before adapting. Assistant statements remain historical context. Full scoped details are retrieved separately from clipped adapter previews. Explicit, entity, category, session, catalog and Similar content connections remain distinct; similarity is never saved as a factual relationship.

GET /api/memory/globe returns revision-consistent pages with scope-bound cursors. X-Nova-Client must identify a currently registered local WebSocket connection; server context selects the owner or guest store and scope. Unknown connections and profile/project elevation fail closed. GET /api/memory/globe/record/{id} supplies complete permitted content. POST /api/memory/globe/record/{id}/action delegates correction, forgetting and restoration to validated existing services, with revision checks. No memory text is sent to console, analytics or error reporting.

## Live behavior
The wrapper builds a consistent paginated snapshot in an adapter worker. New committed IDs call addMemory; duplicate IDs/revisions do not grow twice. Edits, removals and relationship changes replace the cached graph and restore selection only if still permitted. Recall uses actual returned IDs, including concurrent additions pending snapshot loading. Reconnect and revision changes reload. WebSocket memory activity and scoped revision notifications remain separate from organizer progress. Ambient records and continuous random packets are disabled; small traveling signals represent real committed saves and recall.

## Daily conversation history
GET /api/memory/globe/history presents one chronological daily timeline containing both speakers from every original session on that day. The approved Europe/Madrid boundary is 4 AM, including daylight-saving changes. Original sessions, timestamps, message IDs and corrections are preserved; grouping does not rewrite archives. Undated records remain unresolved. A day can continue its latest original session. Scoped history, original session inspection, corrections and reversible forgetting remain available in the conversation rail.

## Historical recovery
The subsequent user-authorized broad recovery audited 118 source files using parser version 3, preserving originals and backing up authoritative stores. It added 12 attributed messages and 76 historical context records; 25,725 duplicates and 912 private/forgotten entries were skipped. The durable report retains 176 unresolved entries, including conflicting historical values and malformed trailing data. Original 621 record IDs/current values, existing message IDs and forgotten IDs were verified intact. A repeat preview yielded zero additional records/messages. Credentials and provider configuration were excluded. No additional re-import occurs during this performance iteration.

## Engine patches
Reduced-motion patches were introduced after failing tests: no automatic rotation or traveling/expanding pulses, immediate focus/zoom, preference-change handling and cleanup. Placement is bounded to two million pair computations; background drawing adapts detail and DPR. The later zoom tests first failed for a 70-record category selection limit, offscreen rendering and excessively fast signals. Category selection now includes all real members across period/topic patches and their existing edges. Details page all connections rather than silently cutting them to 40.

Zoom drawing culls offscreen dots and paths using conservative endpoint/control bounds. Cluster halos are bounded to 42 pixels with a small per-frame budget. All selected adjacency remains available for inspection. Individual-node detail draws all its connections; very large collective category views adapt distant edge detail while retaining visible category spokes. Viewport culling and adaptive drawing do not delete graph data. A reusable Canvas scene avoids retracing a still camera, invalidating on data, selection, search, quality, resize, camera and activity changes. Signals last approximately 1–1.3 seconds and use tiny dots. A density benchmark separately measures overview and focused zoom; unmeasured low-end hardware performance is not guaranteed.

## Review and validation
The six approved checkpoints are plan, real-data mount, live growth, recall, old-code removal, and tests/cleanup. Both previous frontend renderers, their worker, helpers and obsolete controls were removed; R3F, Drei and d3-force-3d dependencies were removed. Three remains for the dashboard orb. Existing backend graph endpoints, original memory class bodies, shared text/voice conversations and the Groq organizer remain. Synthetic fixtures live only in tests.

Regression coverage includes schema mapping, all registered categories, lifecycle/scope isolation, deterministic input ordering, similarity refresh, live duplicate notifications, full detail, save/recall concurrency, forget/restore, reduced motion, bounded placement/drawing, daily boundaries and transcript preservation. Browser scripts cover populated desktop/mobile views, 16 theme surfaces, drag/inertia, wheel/pinch, click-to-front, connected navigation, hover, Escape, dismissal and resize. The benchmark report records host-specific measurements for real, 5,000 and 20,000 records, including deep zoom and input latency.

## Measured validation, 12 October 2026
264 backend tests, 93 existing frontend unit tests, 20 globe tests, TypeScript and the production build passed. Build warnings remain for the existing calculator eval and large main bundle. Populated desktop/mobile browser checks returned no page errors, retained 2,797 lifecycle-permitted records, 122 category/topic groups and 5,957 real/visual connections. Daily history source inspection passed in both viewports. All 16 theme surfaces matched the canvas/panel background.

Headless Chrome on this Windows host measured about 60 FPS for the real and 5,000-record views. The 20,000-record desktop fixture measured 55 FPS overview and 55.9 FPS focused zoom, with 28.2 ms overview input-to-frame and 17 ms focused input-to-frame. The mobile-sized viewport measured 60 FPS in both modes and roughly 16 ms input-to-frame. Layout setup ranged from 235 to 636 ms. These measurements do not certify a physical 4 GB laptop or phone; detailed results are in frontend/artifacts/memory-globe-benchmark.json. Physical live microphone conversations were not injected during this iteration; existing audio and conversation regressions passed.
