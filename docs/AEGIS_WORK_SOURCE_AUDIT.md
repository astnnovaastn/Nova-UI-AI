## Integration risks

| Risk | Handling |
|---|---|
| Spec screenshots for the toolbar and blueprint are not on disk (`UI Design` has only six, none with the toolbar) | Upstream `CanvasNode` is the reference for the toolbar; the blueprint is built from the written spec. Reported in the test results |
| The job queue's 60-second limit for ordinary actions would kill a run | `work_run` gets the same 600 seconds as research. The orchestrator checkpoints and asks to be resumed before that limit |
| Gemini 503s and Groq rejections stopped runs on 5 November | Retries with backoff, a circuit breaker, explicit fallback, repair of bad citations, and a checkpoint before each stage |
| Groq per-request token limits | Workers get compact evidence with bounded text; the existing 7,200-token ceiling is the default for Groq |
| Multi-model use can cost more | Each run records actual tokens per model, with a run budget and a daily cap |
| No local file or account access in AEGIS Research | Kept as it was (Phase 2 decision). Developer, Office and Manager cards work from pasted text and the web, and say so |

## Implementation plan

Phases follow the specification's order, testing after each:

1. Contracts, provider adapters, capability registry, run store and lead routing.
2. Quick Research end to end.
3. Parallel workers, evidence store, validation and Deep Research.
4. Structured Research and auto-layout.
5. Research category and cards.
6. Four node actions and the request panel.
7. Source window links.
8. Polish and regression.
